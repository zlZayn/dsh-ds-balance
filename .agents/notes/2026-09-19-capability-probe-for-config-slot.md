# 决策：配置槽的能力探测（2026-09-19）

> **状态（2026-09-22）：判据已被
> [2026-09-22-config-entry-back-to-bundle-config.md](2026-09-22-config-entry-back-to-bundle-config.md) 取代** ——
> 「盯槽名」换成「盯 `configForms` 服务」。原因是被探测的那个槽（`plugins.bundle.config`）
> 在 0.1.6 与 0.1.7 **都存在**、且两版都不传 `form`，所以「槽在不在」推不出「拿不拿得到表单」——
> 照旧盯它就是一条恒为真的探测。**探测这个机制本身不变**（三态、可逆、只喂提示不参与注册、
> 英文 `[WARN]`、不查版本号），变的只是它盯哪一环。下文保留作历史。

## 问题

配置卡片注册在宿主槽 `plugins.bundle.config` 上。旧宿主根本没有这一格：
`ctx.slots.inject` 会**一直等下去** —— 不注册，也不报错。用户看到的现象是「插件页里没有配置区」，
没有任何解释，也没法自己判断是装错了、坏了，还是宿主太旧。

「查到宿主版本再决定」这条路走不通：客户端半边拿不到宿主版本（没有 hostVersion / appVersion 一类通道），
宿主半边也解析不到 dsh 本体。能问的只有当场可观测的事实：**那一格在不在**。

## 事实（当时实测）

- 新宿主上这一格由 `ui-plugin-manager` 的浏览器半边在**自己的 `apply` 期**随 `main` 注册的
  `children` 一起声明 —— 不是打开 Plugins 页才声明。所以「注册 + 给一个上限」在旧宿主上不会误报。
- `ctx.slots.inject(name, cb)` 的 `cb` 只在声明到达时跑；声明晚到会重新触发它。
- `SlotCore` 那套 `spec` / `declarationEpoch` 观察面同样要等声明，问不出「宿主有没有这个概念」。

## 决策

- **运行时不查版本号，只探测能力**：注册照旧，另起一个上限计时器；到点仍未声明才判缺槽。
  上限给宽（15 秒）—— 宁可晚说，也不要在新宿主上误报；误报会把这个信号本身变得不可信。
- **三态且可逆**：`pending` / `available` / `missing`。声明晚到会把 `missing` 拨回 `available`，
  已经出现的提示自己撤掉 —— 宿主将来改成延迟声明也不会留下误报。
- **提示落在侧栏浮层**：本仓有跨版本 UI 面（余额圆环 + 浮层在分水岭两边都在），
  所以不必退到控制台。文案英文、`[WARN]` 前缀、无 emoji、不带动作按钮。
- **探测不参与注册，也不中断任何功能**：圆环、浮层、后端与探测成败无关。

## 替代方案

- **查宿主版本号再判断**：本仓拿不到版本（见上），否决。
- **什么都不提示，只写文档**：用户不会去读文档；而「静默」正是要修的那件事。
- **只往客户端控制台打一行**：本仓有跨版本 UI 面，按优先项应落在 UI 上；
  控制台留作「确实没有任何跨版本 UI 面」时的退路。
- **固定延时后一次性判断（不可逆）**：宿主将来若改成延迟声明，就会留下一条永远撤不掉的误报；
  改成可逆三态后这个失效模式消失。
- **装一个探测用的子插件 / 安装后脚本**：动了安装面，且 pnpm 默认拦生命周期脚本 —— 不做。

## 影响

- 多一个 15 秒计时器：浏览器半边 `apply` 期建，随插件 fiber 释放（`ctx.effect`）。
- 用户可见：旧宿主上浮层多一行 `[WARN]`。文案**刻意不进** [locales.ts](../../src/client/locales.ts) 的双语词典 ——
  兼容性硬约束要求提示一律英文，放进词典反而会让中文用户读到英文、等于两处都在说谎。
- 判据落点：用户怎么看这件事写在根 [README.md](../../README.md) 的「版本兼容」一节；
  维护者什么时候要动那一条写在根 [AGENTS.md](../../AGENTS.md) 的「文档网络与自更新」。
- 回归面：三态与可逆性由 [test/config-slot.test.ts](../../test/config-slot.test.ts) 用假时钟钉住（不依赖真实时间）。
