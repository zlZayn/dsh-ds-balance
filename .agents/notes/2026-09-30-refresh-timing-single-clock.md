# 刷新计时：上游一个节拍器，冷却一个权威

状态：生效

**类型**：决策记录（问题 / 事实 / 决策 / 替代方案 / 影响）。
**缘起**：维护者报「手动刷新设 5 秒，点完却从 6 秒开始倒数，时间对不上」，并怀疑是刷新本身慢。

## 问题

三处计时各算各的，界面上看到的秒数因此不是真的：

1. **多算一秒**：冷却截止是精确时刻（`Date.now() + N×1000`），而界面里的「现在」是每秒采样一次的 state。
   两者不同刻，`Math.ceil` 就必然多出一秒 —— 5 秒的冷却**恒**显示成 6 秒；
   更糟的是按钮禁用判据也用这个值，等于真的多禁一秒。
2. **两套锚点**：后端从 `snapshot.fetchedAt` 起算，客户端从「刷完那一刻」起算，相差一个往返；
   而后端从**上一次抓取**起算意味着**一次自动刷新会吞掉用户刚按下的一下**：界面转圈、倒计时也走，上游一次没打。
3. **权威被丢掉**：`POST /refresh` 回的 `{ triggered, cooldownMs }` 客户端一个字段都没接，
   被拒绝也照样从满格重新倒数。
4. **节拍越界**：健康态调度延迟是对称 ±20%（48–72s），而缓存窗口就是 `serverRefreshSeconds`（60s）——
   有一半轮次的窗口先过期，界面一次普通轮询就会自己穿透上游抓一次，紧接着这一轮 tick 又抓一次。

## 事实（实测）

- 到 `api.deepseek.com` 一个冷连接往返 **186 / 213 / 251 ms**（DNS 16–32、TCP 33–52、TLS 58–106、TTFB 186–251）。
  ⇒ 「点刷新要等一秒才拉到」不成立；那一秒来自第 1 条。
- 落盘（1.5 MB 的 `ds_balance.json`）**≈6 ms**（快照 `fetchedAt` 与文件 mtime 之差）。
- 本地 3608 个快照间隔：2923 落在 48–72s（调度节拍）、**158 对相隔不足 3 秒**。
  这 158 对里 **117 对的前一个间隔超过 60 秒**（= 窗口已过、轮询代打）、37 对不足 48s（改配置重排 / 启动）、3 对落在 48–60s。

## 决策

1. **客户端的倒计时一秒不差**：截止时刻与展示用的「现在」在同一个 commit 里设（[src/client/model.ts](../../src/client/model.ts) 的 `cooldownUntilOf` / `cooldownSecondsOf`）；解禁落在截止时刻上（一条一次性定时器），不靠每秒走钟。
2. **冷却的权威在后端**：`triggered: false` 时按响应里的 `cooldownMs` 收尾，不拿配置值重数一遍。
3. **服务端冷却锚在「上一次手动刷新」**（`BalanceService.lastManualRefreshAt`），不是上一次抓取；时刻取**决定触发那一刻**，比客户端早一个往返 ⇒ 客户端更保守，按钮亮起时按下去一定真的会抓。
4. **健康态单边抖动**（`jitterWithin`，`[base × 0.8, base - SCHEDULE_GUARD_MS]`）：把「tick 不越过缓存窗口」变成结构保证，那 1 秒余量留给这一轮抓取本身。退避与缺密钥重试仍是对称抖动 —— 它们本来就在窗口外。

## 替代方案（想过，为什么不选）

1. **客户端冷却锚在「点击那一刻」**。不选：比后端窗口早一个往返，按钮亮起后按下去可能被后端拒绝 —— 又变回「点了没反应」，只是换了个方向。
2. **只改客户端把 6 改成 5**。不选：后端锚点不动，「自动刷新吞掉手动点击」还在，只是看不见了。
3. **把缓存窗口放宽到 `base × 1.2`**（72s），不动抖动。不选：流量不增，但「数据最多一个周期旧」的承诺松掉 20%，而配置字段的名字就是刷新频率；单边抖动的代价只是平均间隔 60s → 53.5s（约 +12% 请求量）。
4. **客户端镜像后端窗口：自动刷新后 5 秒内禁用按钮**。不选：每 60 秒就有 5 秒按钮是灰的，而用户看不出原因；「权威在后端 + 客户端只在自己刷完后冷却」更简单，也解释得清。
5. **让 `GET /api/v1/balance` 永不触发抓取**（上游只留一个节拍器）。想过：它能顺手消掉启动时「轮询代打 + 首拉」的相邻两次抓取，但那是契约变更（§8 写的是「过期则抓」），而缓存不可服务时轮询代打正是恢复可见性的来源。本轮不动，记在这里备查。

## 影响

- 浮层冷却从 N 开始倒数、禁用正好 N 秒；健康态上游不再出现相隔不足 3 秒的连击；手动点击一定真的抓。
- 抓取节奏从 48–72s 收到 48–59s（平均 60s → 53.5s）。
- 仍然存在的边界：缓存不可服务（首次加载或失败态）时，界面轮询会代打一次 —— 这是恢复可见性的来源，受轮询周期上限约束；启动那一刻最多多一次请求。
- 被吞掉的手动刷新应当趋近 0：`GET /api/v1/healthz` 的 `force_rejected_total` 现在只在多标签页并发点击时才会涨。
