# notes/ — 规则层

继承根规则，见 [../../AGENTS.md](../../AGENTS.md)。

notes/ 特有约束：

- 一条一档。
- **装两类，判据是「它在回答什么」**：
  - **决策类**：面对岔路口，选了 A 不选 B。**必有「替代方案」**（试过什么、为什么不行）
    + 状态行。文件名 `YYYY-MM-DD-<主题>.md`，日期是**首次提出**那天。
  - **依据类**：勘察 / 评估 / 审查 —— 「为什么这么定」的**输入**。**状态行必有**
    （依据也会过时，也要标 `已归档` / `被取代`）；**「替代方案」可选**（它面对的不是岔路口，
    是未知，本来就没有被打败的选项可记）。**文件名沿用原名，可省日期** ——
    它是「一份判定」不是「某天的决策」，日期对它没有语义。
- **不建索引文件**：目录树 + git 历史就是索引，这里只放记录本身。
- **不建子目录分类**：两类平铺在同一层，用状态行与命名区分，不靠目录分桶。
- **写死当时的事实**，不随代码更新；事实性变化（路径 / 默认值 / 机制名）就地改，决策反转才新写一条并交叉引用。
- 骨架：决策类用 问题 / 决策 / 替代方案 / 影响；依据类用 结论 / 依据 / 影响（或按体裁自定）；
  备忘类用 事实 / 处置 / 影响。
- **第 5 行写一行「类型」**：取值**只有两个** —— 决策类写 `**类型**：决策。`，
  依据类写 `**类型**：依据。`；括号里可补体裁（如 `依据（勘察）。`）。
  **新文件遵守，老文件不追改** —— 历史那批 `**类型**：决策记录（问题 / 决策 / …）`
  是当时的写法，按「不追改」留在原地。

## 状态标记

第 3 行放一行状态，四值之一。**两类都必需** —— 决策会失效，依据也会过时。
状态行是元数据，不属正文；正文从第一个 `##` 起。

| 状态 | 含义 | 必附 |
| --- | --- | --- |
| `状态：生效` | 当前有效，指导未来工作 | —— |
| `状态：被取代` | 已被后续决策整体或部分取代 | 下一行指针，指向取代它的那条 |
| `状态：已否决` | 提案被否，未实施 | 同行一句话理由 |
| `状态：已归档` | 不再指导未来工作 | 同行日期 + 一句话理由 |

四种写法：

- `状态：生效`
- 第 3 行 `状态：被取代`，第 4 行 `指针：[<标题>](<文件名>.md)`
- `状态：已否决 —— <一句话理由>`
- `状态：已归档（YYYY-MM-DD）—— <一句话理由>`

## 归档规则

- 不再指导未来工作时**就地标记**：状态改 `状态：已归档（YYYY-MM-DD）—— <一句话理由>`。
- **不移动文件、不建 `archived/` 目录**；状态行就是归档的标记。
- 归档后冻结：正文不再更新，只留历史价值。
- 部分被取代不新建文件、不归档：保留原记录，状态改 `状态：被取代`，指针给取代它的那一条。
- 决策反转才新写一条并交叉引用；不改写旧记录的正文。
