# 文档一致性审计的收口：留下结论与根因，不留下那份逐条清单

## 问题

2026-09-17 做过一次文档一致性审计，记录在 `recon/12-doc-audit.md`（`recon/` 是被 gitignore 的勘察目录，
按决定已整体删除）。它查出 **18 条与代码矛盾 / 3 条过时数字 / 6 条措辞可优化 / 7 项文档缺失**，
并给出根因：

> **三个 commit 里「文档网络与决策记录」早于「UI 实现」，此后 UI 又经历四轮变更
> （浮层改点击、浮层换官方皮肤、分组改可折叠、删「启用左下角」），
> 而 `README.md` / `docs/ARCHITECTURE.md` / `.agents/notes/` 都没有回头同步。**

recon 要整体删除，所以这份审计的**结论**必须归位到这里。

## 决策

**归位它的结论与根因，不抄那份逐条清单。**

那份清单是对 **2026-09-17 文档状态**的快照：它按 `文件:行号` 定位，
而文档此后已多轮更新 —— 抄进决策记录等于新造一批必然过时的行号。
**要复查就重跑一次审计**：判据不是那份清单，而是「文档描述与代码是否一致」这个问题本身。

## 替代方案

- **把 34 条逐条抄进来** —— 否。行号已漂；且其中相当一部分在审计之后已经修掉了
  （典型：`src/client/sidebar/README.md` 当时指向 `recon/10-footer-layout.md`，
  现已改为指向根 `AGENTS.md` 的「活跃坑」与决策记录）。
- **什么都不记，直接删** —— 否。丢掉的不是清单，是那条**根因**：文档晚于代码。
  它是「改动波及的文档必须同批更新」这条规矩的来源，而那条规矩现在还在这两处生效：
  根 `AGENTS.md` 的「文档网络与自更新」，以及每个子目录 `README.md` 的「变更影响路由」。

## 影响

- 本次顺带修掉审计 B 类里**唯一还确定成立**的一条：`docs/recon-native-integration.md` 里
  「原始长文在 `recon/`（当前 12 份，编号 00–11）」—— 它既已漂（实际 18 份），
  又随 `recon/` 删除而失效，所以整行删掉。
- 长效对策不是清单，而是同步点：**改一处要查得到同步点**。
  这条已写在根 `AGENTS.md` 的同名条目里，并由各子目录 `README.md` 的「变更影响路由」承载。
