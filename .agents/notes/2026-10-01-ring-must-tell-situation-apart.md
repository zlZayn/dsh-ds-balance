# 收回「两处刻意同形」：环要能自己说清处境

状态：被取代

指针：[形态矩阵审计](2026-10-01-render-matrix-audit.md)

**类型**：决策记录（问题 / 事实 / 决策 / 替代方案 / 影响）。
**缘起**：维护者要求「先核实实情，再动手」，核实两处**收起态圆环**的歧义：

- ① `checking`（加载中）与 `empty-wallet`（账户没钱）；
- ② `account-unavailable`（账户停用）与 `critical`（余额恰好为 0）。

## 问题

[形态矩阵审计](2026-10-01-render-matrix-audit.md) 把 ② **写成了断言**：
「两组同形是刻意的，靠文案与浮层金额区分」。这轮要求复核这条到底成不成立。

## 事实

**核实方法换了一层**：不是再读一遍形态表，而是把**真组件**渲出来
（`renderToStaticMarkup(<PercentRing …>)`），按**看得见的通道**取指纹 ——
颜色 / 弧长 / 记号（按**坐标**判朝向，叉与＋都是 2 条 `<line>`，数条数会判成同形）/ 是否转动。

结果两处**都成立为真歧义**，且都是**逐像素相同**：

| 处境 | 色 | 弧 | 记号 |
| --- | --- | --- | --- |
| `checking` | idle | 无 | 无 |
| `empty-wallet` | idle | 无 | 无 |
| `account-unavailable` | error | 无 | 无 |
| `critical`（余额 0） | error | 无 | 无 |

**为什么读形态表看不见**：表里写 `arc: 'gauge'`，意思是「弧长按余额比例算」；
而**余额恰好为 0 时 `ringRatioOf` 返回 0、根本不画弧**。
「声明不同」与「画出来不同」是两件事 —— 只看前者必然漏掉后者。

**原判断错在哪**（②）：说「这两者靠浮层文案与金额区分就够了」——
可**收起态里没有文案**（只有环）。用「别处能区分」去论证「这里不必区分」，
在一个用户首先看到的形态上不成立。

**顺带发现的第二条教训（比第一条更值钱）**：`render-matrix` 第一版读的是形态表，
而形态表就是它的**唯一真相源** —— 两边一起错时它**必然全绿**。
它当时确实全绿。改成渲真组件之后，「应该」与「实际」才成为两份独立证据。

**第三条教训**：`account-unavailable` 的叉是被一次重构**静默丢掉**的（详见下面「决策」第 2 条的补记）。
丢掉它时，**测试与代码一起改了**（旧断言被删、新断言写 `null`），所以测试没拦住；
而**文档没跟着改**，于是文档与代码长期矛盾 —— 双方各自的检查都不覆盖这种「跨半边的一致性」。
可复用的判据：**重构时若某条断言的期望值被改了，要问「这是决策变了，还是搬运丢了」**。
本次的搬运丢失能存活这么久，正因为它在提交信息里没有被提及。

## 决策

1. **`checking` 用官方 `StateDot` 的 `ongoing` 不完整转弧**，自成一族 `pending`。
   - 为什么必须**不完整**：圆是对称的，整圈转等于没转，只有缺口在动才看得出来；
   - 弧长取官方 `12 / (2π×9.5)` 的**同一比例**（本组件半径不同，各自网格里看起来一样长）；
   - 不叠官方那条呼吸（dasharray 12↔24）：它会和「弧长 = 余额占比」的读法打架；
   - 减动效时停掉旋转、**保留静态弧** —— 连弧一起藏就又跟空环撞上了。
2. **`account-unavailable` 加叉**，并**移出 `gauge` 族**（那族的定义是「有数字」）。
   叉的语义从「读不到」扩为「读不到**或用不了**」：都属「这里没有可用的数字」，用户动作都是去查。

   **补记（核实 git 历史后）**：这个叉**不是新加的，是恢复**。
   处境重构之前 `model.ts` 的 `ringSpecOf` 就是
   `marker: severity === 'unavailable' ? 'cross' : null`，
   且当时的 `test/model.test.ts` 有两条断言守着它（「只有 unavailable 画中心符号」）。
   重构（`ecb5114`）把它搬进形态表时写成了 `marker: null`，
   而重构的提交信息**只在讲别的缺陷**，没提这一处 —— 于是它静默丢了。
   文档侧反而没丢：`docs/ui-handoff.md` 一直写着「后者多一个中心叉号」，
   所以那段时间**文档与代码是矛盾的**，而两边各自的检查都不会发现。
   本轮先是照「两处歧义」把它当新增修掉，翻历史才发现是**回归**。
   这也解释了为什么最初那张「刻意同形」表会把 ② 当成「有意接受」——
   它是在为一次**没人注意到的回归**补理由。
3. **新增不变量**：**跨族同形 = 歧义，必须为 0**；同族同形状；
   颜色只有 `gauge` 族允许随 `severity` 变。
   （后两条我写错两次才对：`gauge` 族的**颜色和弧长都是读数**，族内本就该不同。）
4. **族数 4 → 5**（拆出 `pending` / `empty`）。族的定义就是「屏幕上长得不一样」——
   合并两族付出的代价，正是这两处歧义本身。

## 替代方案（想过，为什么不选）

1. **只改 `checking`，`account-unavailable` 维持现状**（保留原判断）。
   不选：核实证明那条判断是错的（收起态没有文案可依靠），不是「取舍」。
2. **让整条圆环转起来表示「加载中」。** 不选：圆是对称的，转起来看不出来。
3. **给 `checking` 发明一个新记号**（例如省略号）。不选：会多出一个只有本插件懂的符号；
   官方 `StateDot` 的 `ongoing` 语义正好是「进行中」，且已有实现可对照。
4. **`account-unavailable` 换成别的颜色**（例如琥珀）。不选：账户停用是**坏消息**，
   用「警告色」会削弱它的严重度；叉是更准确的通道 —— 它说的是「这里没有可用的数字」。
5. **把两者合并成一族、靠文案区分。** 不选：同上，收起态没有文案。

## 影响

- 两处歧义消除；`render-matrix.test.ts` 里那条「有意接受的同形」断言被**反转**为
  「两枚红环不再同形」。
- **同源缺陷**：`legacySituationOf`（旧宿主兼容层）漏搬了 `stale` 的前提 ——
  `state === 'stale'` 判在 `selected === null` 之前，会对着空界面说「数据已过期」。
  **同一份判定写了两个半边时，修一处不算修完。**
- **测试基建**：为了让这些断言能**渲真组件**，`vitest.config.ts` 开 `esbuild.jsx`，
  `tsconfig.test.json` 开 jsx / DOM lib / css-modules 声明。
  在此之前测试 import 任何 `.tsx` 都报 `React is not defined` ——
  两处歧义正是这样躲过审计的。
- 未做（属附加项，见交付报告）：「超时降级」（旧快照太久转灰）经核实**几乎不可达**，
  不做；`prefers-reduced-motion` 已处理。
