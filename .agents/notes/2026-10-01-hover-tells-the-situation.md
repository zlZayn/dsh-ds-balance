# 决策：悬停文案两态同源，且只在数字可信时报数字（2026-10-01）

状态：生效

**类型**：决策记录（问题 / 事实 / 决策 / 替代方案 / 影响）。
**缘起**：维护者要求「收起态和展开态悬停显示同样的东西」，并裁定基准改为
**数字可信才显数字，否则显状态文案** —— 理由是账户停用 / 数据过期时那个数字
不可信或不可用，报它反而误导；环已经画了问题（红叉 / 旧色），悬停该解释问题。

## 问题

两态此前**各算各的**，是两条独立的路：

- 收起态（56px 轨道）用 `ringTitle`：`!wide && stateText !== null ? 「DeepSeek 余额状态 」+ stateText : undefined`；
- 展开态用 `hoverLabel`：`shown === null ? stateText : formatMoney(...)`。

两条路的**判据不同**（一个看 `stateText`、一个看 `shown`），**优先级也相反**，
所以必然分叉 —— 与处境重构之前「环 / 文案 / 标签各拼各的」是同一类病。

## 事实

把真组件渲出来（`renderToStaticMarkup(<SidebarBalance wide={…}>)`，两态各一遍）实测到三种不一致：

1. **收起态在 `ok` / `low` / `critical` 上什么都不显示**：这三个处境的 `textKey` 是 `null`
   → `stateText` 是 `null` → `ringTitle` 是 `undefined` → 那个 `<svg>` 里**连 `<title>` 都没有**。
   实测：`有 <title>：false`。
2. **`stale` 上两态各说各的**：收起态显「DeepSeek 余额状态 数据已过期」，
   展开态显旧金额 —— 同一个屏幕上两个说法。
3. **收起态多一个前缀**（「DeepSeek 余额状态 」），同一个处境两态文字不同。

另外核实到：`account-unavailable` **可能带着数字**（mock 的 `unavailable` 场景就是一条 ¥0），
`stale` 更是必然带着一份旧数字。所以「有没有 `shown`」与「数字可不可信」**不是一回事**。

## 决策

1. **文案收敛到一个函数**：`client/situation.ts` 的 `hoverTextOf(shown, stateText)`，
   两态都取它的返回值。**「说什么」只有一处**，交付通道仍分两条
   （收起态 SVG 原生 `<title>`、展开态官方 `Tooltip` 原语）——
   那是「怎么显示」的差别，与「说什么」无关。
2. **判据是「这个处境有没有话说」，不是「有没有数字」**：写成 `stateText ?? 金额`。
   `textKey` 只在 `ok` / `low` / `critical` 上是 `null` —— 那三个正是**数字可信**的处境；
   其余八个（含**有数字的** `stale` 与 `account-unavailable`）显文案。
   这不是巧合：文案表与形态表是同一份声明（`SHAPES`）。
3. **收起态不再加前缀**：两态文字必须逐字相同。

## 替代方案（想过，为什么不选）

1. **按 `shown !== null` 判（有数字就显金额）。** 不选：会让 `account-unavailable` 显「¥0」、
   `stale` 显旧金额 —— 正是维护者指出的误导。这两处的数字要么不可用（账户停用），
   要么不可信（快照过期）。
2. **按 `family === 'gauge'` 判。** 不选：`stale` 归 `gauge`（数字是真的、只是旧），
   按族判还是会显旧金额，与裁定不符。（这条曾经实现过一版，被本轮裁定推翻。）
3. **两态各算各的，只补一条测试对齐。** 不选：那是**靠两处对齐**，不是结构保证 ——
   下次改一处就再分叉一次。收敛成一个返回值之后，两态**不可能**不一致。
4. **收起态也挂官方 `Tooltip` 原语（统一交付通道）。** 不选：rail 是 56px 轨道、
   没有可见文字，原生 `<title>` 已经够用；原语要 portal + 定位，
   而这一格与左邻条目紧贴，多一层定位就多一处可能与邻居的悬停区互相干扰。
   **通道不同是有意的**：收起态没有别的载体，展开态已经有可见标签。
5. **收起态保留「DeepSeek 余额状态 」前缀**（rail 没有可见文字，前缀提供语境）。
   不选：它让同一个处境两态文字不同，而维护者的要求正是「显示同样的东西」；
   语境由 `aria-label` 承担（它本来就带 `sidebar.aria.ring`）。

## 影响

- **悬停现在总是有话说**（两态、11 个处境全覆盖）。从前收起态在一半处境上是空的。
- `stale` 的「数据已过期」**第一次有了收起态可见的出口** —— 从前它只出现在
  `aria-label` 里，收起态的悬浮什么都不显示。
- `account-unavailable` 不再显「¥0」，改显「账户不可用」。
- 新增守卫 `test/hover-parity.test.ts`：渲两态真组件、从 DOM 里各读一次实际显示的内容，
  逐条比对，并钉住「`stale` / `account-unavailable` 有数字也不显数字」这条反向断言。
- 文案的真源仍是 [locales.ts](../../src/client/locales.ts) 的 `situation.*`（七条）；
  悬停规则写在 [docs/ui-handoff.md](../../docs/UI-HANDOFF.md) §四。
