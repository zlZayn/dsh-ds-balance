# 浮层不显示状态文案（为什么这是有意的）

状态：生效

**类型**：决策记录（问题 / 事实 / 决策 / 替代方案）。
**缘起**：第二轮改悬停文案时被问到「浮层里到底显不显示状态文案」。
答案是不显示，但这条**从来没被写下来过** —— 代码里只有「没有」，没有「为什么不」。
不写下来，下次一定有人把它当遗漏补上，而补上会让界面上出现**两处**说同一件事。

## 问题

没有数字时，浮层长这样：

```
余额      --
赠送      --
充值      --
刚刚更新
```

三行 `--`，**没有任何一句话解释为什么**。用户能拿到的唯一解释是**悬停气泡**里
那一句处境文案（「读不到余额」/「尚未配置凭据」/…）。

这看起来像个缺口：为什么不在浮层里也写一句？

## 事实

- **浮层的 props 里根本没有处境或错误**（实测：`situation` / `error` 字段 0 处）。
  它只收 `selection` / `ageMs` / `sourceLabel` / 刷新态这些展示用的东西。
  所以「不显示」在当前结构下是**默认结果**，不是有人特意删掉的。
- 浮层里**已经有**一行状态：页脚那个 `role="status"` 的 `statusText`，
  但它说的是**刷新**（「正在刷新」/「{n} 秒后可再次刷新」），不是**处境**。
- 悬停气泡与浮层是**同一份处境文案**的两个出口（都来自 `presentation.textKey`）。
  在浮层里再加一处，就是同一句话在同一个组件树里出现两次。

## 决策

**保持不显示。** 理由分两条，一条是分工，一条是结构：

1. **分工**：悬停回答「这个环现在是什么意思」（**状态**），浮层回答「余额是多少、
   什么时候更新的、从哪条来源来的」（**数据**）。把状态塞进浮层，两个界面的职责就重叠了 ——
   而重叠之后必然要回答「两处不一致时信哪个」，那是一整类新问题。
2. **结构**：浮层要显示处境，就得把 `situation` 一路传进来，于是它也要知道
   「什么叫处境」。**客户端知道得越少越优雅** —— 浮层是个纯展示组件，
   它现在对处境的全部认知是零。为了多一行字把它变成处境的消费者，不划算。

**这不是「暂时没做」**：如果将来浮层真的需要解释（例如用户反馈「点开只看到 `--`，
不知道怎么回事」），正确的做法是**把状态行做成浮层的一等元素**（连同它的位置、
与刷新状态行的关系一起设计），而不是把悬停文案复制一份进去。

## 替代方案（想过，为什么不选）

1. **直接把 `textKey` 也传给浮层，在三行 `--` 下面加一句。**
   不选：那是把悬停的文案复制进浮层，两处会各自漂移；
   而且它没回答「这句话和页脚那行刷新状态是什么关系」。
   真要做，应当先定那一层信息架构。
2. **把处境编码进那三行的标签**（例如「余额（读不到）」）。不选：标签是数据名，
   不是状态容器；混在一起之后，读屏用户会先听到一个残缺的字段名。
3. **让浮层也在没有数字时显示「暂无数据」之类的中性话。** 不选：
   中性话等于没说 —— 用户需要的是**为什么**（没配凭据 / 读不到 / 账户停用），
   而那正是处境文案的职责，它已经在悬停里给了。

## 影响

- 没有数字时，**悬停气泡是唯一解释**。这条约束落在
  [src/client/locales.ts](../../src/client/locales.ts) 的处境文案上：
  每一句都必须能单独回答「为什么这里没有数字」，不能说只有配合上下文才读懂的话。
  理由与最终表见那里的注释和 [test/locales.test.ts](../../test/locales.test.ts) 的断言。
- 一处**已知的体验缺口**（本轮**只有代码追踪、没有渲出来**，见交付报告）：
  浮层翻开时若一份快照都还没有，页脚那行年龄会显示「刚刚更新」——
  它来自占位视图的 `ageMs = 0`（`pendingView()`），并不是真的更新过。
  **证据强度**：`pendingView().ageMs === 0` → `ageBucket(0).bucket === 'just-now'`
  → 词典 `popover.updated.justNow === '刚刚更新'`，三步都是读代码 + 已通过的单测；
  没能渲出浮层本身（ui-primitives 在测试环境里加载不了，见 vitest.config.ts 的注释）。
  属于「附加项」，不在本轮范围内。
